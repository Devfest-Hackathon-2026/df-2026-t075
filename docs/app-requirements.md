# アプリ要件

2026年11月10日改訂。18歳以上の利用者が、オンラインの部屋で話し合い・勉強会・グループワークをするWebアプリを作る。各部屋にはAIのメンバーが1人参加し、会話を聞きながら進め方づくり・時間・順番・メモを受け持つ。人数が多いときは主催者が部屋をグループに分け、各グループにもAIメンバーが入る。

11月6日版の「AI先生が授業をする教室」から方向を変えた。変えた理由と引き継がない要件は[末尾](#11月6日版から方向を変えた理由)にまとめる。プロダクト名は AInote（11月8日に決定）。現在はGoogleログイン、Firestoreに保存する部屋の作成・招待・入退室、サンプルデータを使うUIプレビュー、Firestore・Functionsの疎通基盤まで実装した。

## 解決したい課題

| 場面               | 起きること                                                       |
| ------------------ | ---------------------------------------------------------------- |
| 少人数の話し合い   | 話が止まる。誰も仕切りたがらない。時間を忘れる                   |
| 人数の多い話し合い | 一部の人だけが話す。話が逸れる。時間内に終わらない               |
| グループワーク     | 主催者（先生・講師）が全グループを同時に見られない               |
| 立場の差がある場   | 「話が逸れている」「時間が過ぎている」と言いにくい               |
| 学びの場           | 考えを言葉にした人ほど理解が進むが、黙っている人はその機会を失う |

これらは仮説であり、想定する利用者にはまだ確かめていない。想定する利用場面は、大学の授業・ゼミ、企業研修のグループワーク、友達や同僚との勉強会・輪読会。

## 既存サービスとの違い

2026年11月7日の検索では、会議の議題と時間を管理するAI（Microsoft Teamsの[Facilitator](https://support.microsoft.com/en-US/teams/copilot/facilitator-in-microsoft-teams-meetings)、[Zoom AI Companion](https://siliconangle.com/?p=711658)）と、会議に参加して会話するAIアバター（[HeyGen](https://www.maginative.com/article/heygens-new-interactive-avatar-joins-zoom-calls-so-you-dont-have-to/)など、主に本人の代理出席）はすでにある。発言の少ない人に促す仕組みは、[Stanford Online Deliberation Platform](https://deliberation.stanford.edu/tools-and-resources/online-deliberation-platform)など研究や教育での試みが中心だった。調べたのは英語と日本語の検索の範囲だけで、見落としはありえる。

このアプリでは次の点を重視する。

- AIを画面の端の機能ではなく、人と同じ作法でふるまうメンバーとして置く（割り込まずに手を挙げる、うなずく）。
- 進め方を最初から決めておかず、画面に「進め方はどうしますか？」と表示し、話し合いながら一緒に決める。
- 人数に合わせてAIの役割が変わり、2人から大人数のグループワークまで同じ仕組みで使える。
- 議論マップを導入した段階では、AIが未確認の点を覚えておき、結論を出す前に参加者がその論点に戻って補足できるようにする。[論点の状態を使った進行](#論点の状態を使った進行)

## 役割

| 役割       | できること                                                                                                                                               | できないこと                                                         |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 主催者     | 部屋を作る。お題・合計時間・AIメンバーを決める。招待リンクを配る。部屋を終える。グループに分ける・戻す（削る候補）                                       | 個人ごとの発言時間を見る。合図の送り主を知る                         |
| 参加者     | 招待リンクか招待コードで入る。話す。進め方を確定・変更する。時間を延長する。次のパートへ進める。メモを書き足す。議論マップを訂正する（その次）           | 部屋を終える。グループ構成を変える                                   |
| AIメンバー | 進め方の案を作る。進行、問いかけ、パートごとのメモ。「AIに話す」で頼まれたことに会話を踏まえて答える（調べものと出典共有を含む）。進め方の変更を提案する | 確定した進め方を自分で変える。主催者だけの操作。頼まれずに話し始める |

主催者も、グループに分けていない間は参加者として話し、参加者と同じ操作ができる。招待リンクを持つだけでは主催者の権限は得られない。主催者に見せるのはグループ全体の発言の偏りだけで、個人ごとの発言時間は見せない（[参加条件・プライバシー・権限](#参加条件プライバシー権限)）。

## 人数とAIメンバーの役割

| 人数    | AIメンバーの主な役割                                                   | 主催者の動き           |
| ------- | ---------------------------------------------------------------------- | ---------------------- |
| 2〜3人  | 一緒に考えるメンバー。問いを投げ、別の見方を出し、メモと時間を受け持つ | 参加者として話す       |
| 4〜6人  | 司会。順番、発言の偏り、脱線、メモを受け持つ                           | 参加者として話す       |
| 7人以上 | グループごとの司会と、全員が戻ったときの発表の進行                     | グループに分けて見守る |

どの人数でも同じ部屋の仕組みを使い、作成時に「少人数用」「研修用」などを選ばせない。1グループの人数上限は未決定で、提出時は最大4人とAIメンバーで確かめる。

## 部屋の流れ

部屋は「開始待ち → 進め方を決める → パート（いくつか） → 振り返り」の順に進む。最初と最後は固定で、間のパートは部屋ごとに参加者とAIメンバーが決める。決まった型を最初から当てはめないのは、話し合いの中身に合わせた進め方のほうが、参加者が納得して進められるため。

| 段階           | AIメンバーがすること                                                   | 画面で伝えること                                           |
| -------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------- |
| 開始待ち       | 画面で入室を知らせる                                                   | 誰が来ているか                                             |
| 進め方を決める | 最初の問いを画面に出し、会話に合わせて進め方の案を直す                 | 進行メモに進め方の案。直す・確定する操作。残り時間         |
| パート         | 見守り、時間・発言の偏り・沈黙に対応し、会話からそのパートのメモを書く | 今のパートと残り時間。進行メモで各パートのメモを開閉できる |
| 振り返り       | 画面に終了と振り返りの問いを出す                                       | 本人の発言時間と「言いたいことを話せましたか」の問い       |

通話が有効な部屋では、入室前の同意を済ませて「入室する」を押すと、そのまま聞き手として通話につながる。主催者の入室やマップの表示は待たない。マイクは最初はオフで、会議画面で各自がオン・オフを選ぶ。議論マップを開閉しても、通話や文字起こしは途切れない。

入室した参加者は、自分の画面だけ議論マップを全画面にできる。参加者の映像は移動・折りたたみできる小窓に表示し、カメラがオフの人は名前と頭文字で示す。全画面を終了しても、通話、マイクとカメラの状態、選んだマップの項目はそのまま保つ。

参加者はどの段階でも話せる。順番はAIメンバーからのお願いであり、サーバーでマイクを止めない。強制すると相づちや補足もできなくなり、話し合いが止まるため。

### 進め方を決める

1. 主催者が部屋を始めると、全員の画面に「進め方はどうしますか？」と表示する。参加者はそのまま話し始められる。
2. AIメンバーは、お題・合計時間・それまでの会話から進め方の案を作り、進行メモに出す。案はパートの並びで、各パートは名前・ねらい・時間を持つ。
3. 参加者が話した内容（「最初のパートは短くしよう」など）に合わせて、準備中はAIメンバーが共有の進行案を更新する。討議開始後は変更案を画面に出し、参加者が承認する。参加者は画面からも、パートの名前・時間の変更、追加、削除ができる。
4. 参加者の誰かが「この進め方で始める」を押すと確定する。3分たっても確定しないときは、その時点の案で始める。
5. Geminiが案を作れなかったときは、決まった型（例：現状を共有する → 原因を出し合う → 対策を考える → まとめる）を案として出す。

準備中に届いた有効なAI案はすぐに共有予定へ反映し、画面に変更内容を示す。各端末で入力中の下書きは保持する。手動確定後、または準備開始から3分経過後の変更は参加者の承認を待つ。「見送る」を押した場合、同じ版で同じパートに触る自動案は再表示しない。声で頼んだ変更を優先する。

パートの時間の合計は、部屋の合計時間から振り返りの時間を除いた範囲に収める。

### パートを進める

- 今のパートは、進行メモで自動的に開く。終わったパートは閉じて、完了の印を付ける。どのパートも開けばメモを読める。
- 終了予定時刻を過ぎると、次のパートへ進む。参加者は誰でも、早めに次へ進めたり、延長したりできる。AIメンバーも「次に進みますか？」と提案できる。
- 確定後も、参加者はこれからの討議パートを追加・削除・編集できる。終わったパートは固定する。今のパートは開始時刻を保ち、終了が現在時刻より後になる範囲で長さを変えられる。新しいパートは今のパートより後に挿入し、最後の「振り返り」2分を確保する。
- AIの変更案はどのパートをどう変えるか画面に示し、参加者が「この変更を反映する」を押したときに同じ条件で反映する。メモを追記しても変更案は承認できる。先に予定が変わった場合や対象パートが終わった場合は、その理由を表示する。口頭で説明する場合は挙手して「どうぞ」を待つ。
- 誰でも進められるので、押し間違いに備えて、次へ進めた直後の数秒は取り消せるようにする。

### メモ

- 各パートのメモは、AIメンバーが会話から書き、参加者も書き足せる。
- メモは項目を追記するだけで、書かれた項目は書き換えない。複数の人とAIが同時に書いても、どれかが消えないようにするため。
- メモに発言者の名前は出さない。誰の意見かが並ぶと、発言時間と同じく評価されている感じが出るため。

## AIメンバーの要件

### 聞くことと話すこと

AIメンバーは部屋の会話を常に聞いて文字に起こし、メモ・進行の判断・返答の文脈に使う。一方、声を出すのは次の二つの場面に限る（11月9日に決定）。入室・開始・時間切れ・振り返りの案内は画面に表示する。長い沈黙が続いても、AIからの問いかけは挙手して「どうぞ」を待つ。

- 参加者が「AIに話す」を押して話しかけたとき。押した人が話し終えてから答える。
- AIメンバーが手を挙げ、参加者が「どうぞ」を押したとき。

声だけで発言の終わりを判断すると、考えるための間で区切ってしまい、話の途中で返答を始める。11月8日にテストページで実際のマイクを使い、1人で話しても起きた。グループでは相づち・話の重なり・間が増えるので、さらに難しい。人どうしでもオンライン会議では挙手で順番を決めている。押してから話す方式なら、AIは割り込まず、名前の聞き違いも起きない。代わりに、名前を呼ぶだけで話しかける自然さは「その次」に回す。

AIメンバーは、直前の会話・進め方・今のパート・メモを踏まえて答える。最初の道具は、会話で頼まれた進行案の変更を提案するために使う。調べものを追加した段階では、依頼を受けて公開資料を調べ、実行中はタイルに「調べています」と出す。[調べものと出典の共有](#調べものと出典の共有)

### 見た目とふるまい

1. 人と同じ大きさのタイルに参加者として表示し、名前の横に「AI」と出す。人間のふりをしない。
2. 見た目は2Dのキャラクターにし、写実的な映像は使わない。人の話を聞いている間はうなずき、話すときは口を動かす。
3. 人が話している間は割り込まない。自分から話したいときは手を挙げ、参加者が「どうぞ」を押したときに話す。「どうぞ」が押されるまで会話を聞き続ける。
4. AIメンバーが話している途中で人が話し始めたら、話すのをやめる。
5. 話した内容は字幕でも表示する。
6. 見た目・名前・声はプリセットから選び、部屋で共通にする。プリセットの数は未決定。

### 進行

7. 開始時の問いを画面に出し、会話から進め方の案を作って直す（[進め方を決める](#進め方を決める)）。
8. 今のパートの終了予定時刻に合わせて、残り時間を画面に表示する。
9. 発言の少ない人には、まず本人の画面だけに知らせる。本人にも声で呼びかける場合は、挙手に「どうぞ」が返ってから、パスしてよいことを添えて話す。
10. 会話から、パートごとのメモを書く。
11. 前の発言を引用して話をつなぐ。
12. お題やパートのねらいから逸れたと判断したら、戻るかどうかを尋ねる。そのまま続けることも選べるようにする。

#### 論点の状態を使った進行

部屋が続いている間、発言の総数にかかわらず、音声と文字の発言を同じ議論マップに反映する。以前のカードからも根拠になった元の発言を見返せる。

「その次」に追加する議論マップでは、部屋ごとに「何を決めようとしているか」を論点として持つ。論点ごとに候補、合意した条件、決定事項、未確認の点とその確認状況を追う。グループに分かれている間は、そのグループの議論を扱う。

条件は、それを使って判断する論点のすぐ下にまとめ、条件カードには線を引かない。カードを選ぶと、属する論点と元の発言を確認できる。「勉強会をどこで開く？」には開催日と予算の上限が並び、各会場の空きや料金は候補ごとの確認事項になる。開催日時を決める話し合いなら、同じ「12月12日の午後」も候補になる。

候補が条件を満たさないと分かった時点では、その事実を記録する。参加者が予算を優先して案を外そうとしたら、その候補に「見送りの理由」をつなぐ。候補は提案の段階で「見送りを提案」、同意を得た段階で「見送り」となる。逆に会場を優先して予算の上限を上げたら、条件カードに新しい上限と「緩和」を表示する。条件を取り下げたときは「撤回」とする。どちらも理由を選ぶと、判断に使った条件・候補・確認結果と元の発言をたどれる。

論点ごとに左から条件・候補・根拠をまとめ、次の論点との間にはすべての列にまたがる余白を置く。道案内では、美咲が提案した時点で地図リンクの案を表示し、葵が入口写真を提案したらその案と理由を加える。未確認・確認中の質問は該当する候補の真下に置く。答えが出たら同じ項目を右に移し、候補を補強する材料か、見送りの材料かを示して線でつなぐ。室料だけが分かり、機材込みの総額が分からない場合などは、中立の「確認結果」とする。質問と回答はいずれも元の発言に戻って確かめられる。

同じ対象・条件について同じ事実を示すカードは1枚にする。美咲の「机を出しても12人座れる？」に陸が「16席ある」と答えたら、元のカードを「机を並べても16席あり、12人全員が座れる」に更新し、その1枚を駅前案の補強材料にする。別の人が同じ事実を言い換えたら、その発言も同じカードからたどれる。同じ発言で「プロジェクターでスライドも映せる」と分かった場合は、設備についての根拠を別のカードに残す。

数値が案を選ぶ判断に使われたら、あとでその判断を確かめ直せるよう、カード本文に比較した両方の値と単位、値が成り立つ条件を残す。席数なら、参加予定の12人と、机を並べた場合の16席を一緒に読める。調べた経緯などの細部はカードを開いて元の発言で確認できる。

美咲が持っている入口写真は「入口写真を添える」案の補足にする。葵が案内文を引き受けたら、道案内の「やること」に誰が何をするかを記録し、「予約が取れてから」は案内を送るタイミングとして添える。

発言29で会場が市民センターに決まると、参加者には地図のリンクと入口写真で案内する方針が確定する。「参加者にどう道案内する？」は「検討終了」、採用した案は「決定」と表示する。予約や写真の受け渡し、参加者への送信は「やること」に残る。

理由の右に「やること」の列を置く。作業カードは対象の案と上端をそろえ、同じ案の作業が複数あればその行に縦に並べる。論点全体に関わる作業には「論点全体」と表示する。発言29で葵が市民センターの申込みを頼んだら、研修室を予約して結果を知らせる作業を陸の担当として会場案の行に置く。作業を選ぶと、依頼した葵の元発言を読める。

参加者が自分から挙げた利用経験も、候補を支える根拠として扱う。市民センターが20人収容という経験は、参加予定の12人が入れることの補強材料になる。「土曜午後はたしか6千円だった」という話は昨年の記憶として残し、今年の料金は案の下の確認事項にする。

同じ論点の中でも、候補と、その下の確認事項、右につながる理由・確認結果を一組にする。次の候補は、前の組でいちばん下にあるカードの下端から余白を空けて置く。

根拠が続けば右へ、並列の項目が増えれば縦へ広げる。スマホでもこの並びを保ち、その時点の全項目と接続線が枠に収まる倍率で表示する。縮小されたマップは原寸に切り替えて読める。原寸では一番端の項目まで上下左右にスクロールできる。

発言は「どの論点に何を加えたか」という意味のまとまりごとに扱う。たとえば「駅前の会議室がいい。料金は私が調べる」という一言からは、会場の候補が増え、料金が確認中になったことが分かる。後から別の人が「駅前は8千円だった」と報告したら、同じ候補の料金を確認済みにする。

カードの右上には、案なら提案した人、質問や回答ならその内容を述べた人の名前を、その人の色で表示する。項目への賛否を表明した人は、本文の下に 👍（同意）か 👎（反対）と名前だけをまとめて表示する。同じ人が意見を変えたら、その時点での最新の反応を表示する。質問、補足、判断の保留も含め、各人の元の発言はカードを選ぶとたどれる。

予算の上限を1万円と決めていれば、同じ「駅前にしよう」という発言でも、AIの進行は料金の確認状況で変わる。未確認のまま決まりそうなら、AIは手を挙げ、「どうぞ」を受けてから「予算内か確認しますか」と尋ねる。誰かが調べている間は待つ。8千円と分かった後は、料金の確認を終えて次の論点に進める。

参加者は、AIが進行に使う論点と案の関係を議論マップで見直せる。たとえば「駅前はまだ候補」と訂正すると、AIは次の問いかけや結論案でも候補として扱う。会話の内容をマップにして参加者が編集する設計は、Chen ら（2025）の研究を参考にした。[MeetMap 論文](https://arxiv.org/html/2502.01564v1#S3.SS3)

### 話しかけと合図

13. タイルの「AIに話す」を押すと、AIメンバーは押した人の発言を依頼として受け取り、ほかの参加者の直近の会話も踏まえて答える。考えるための間では区切らない。もう一度押す（「話し終えた」）と、すぐに答え始める。答えを作っている間は、タイルに「考えています」と出す。
14. 名前で質問を受け取る（その次）。名前と質問を一息で言われても取りこぼさないよう、最後まで聞き取る。音声で答える場合は挙手して「どうぞ」を待つ。
15. 答えを言う前に問いを返すことを基本にする。AIメンバーが出すのは問いと別の見方までにし、議論の結論は参加者に委ねる。調査を頼まれた事実については出典とともに答える。人が考える前にAIが議論を引っ張らないためで、11月7日に決めた。
16. 参加者が送った合図（話が逸れている、時間が気になる、話したい）を、送り主を明かさずに全員へ伝える。

AIメンバーの名前は、普段の会話に出てこない音にする。例えば「ミナ」は「皆（みな）」と同じ音なので、名前で話しかける機能を足したときに「皆さん」と言っただけで反応するおそれがある。文字起こしの聞き取りヒントにも名前を入れる。

### 障害時

17. AIメンバーを利用できないときも、人同士の会話、残り時間の表示、パートの進行は続ける。進め方とメモは画面から操作できる。AIメンバーが止まっていることを画面に出す。

### 調べものと出典の共有

会員の部屋では、参加者が「AIに話す」を押して音声で依頼すると調査を始める。千葉市民会館の基本料金と世界銀行の総人口を調べられる。

検索中はタイルに「調べています」と表示し、参加者は話し合いを続けられる。結果は見つかった時点で全員の画面に出す。AIは手を挙げ、「どうぞ」の後に要点だけを話す。会議後も、入室したことのある利用者はノートから回答の要旨・適用条件・出典を読み返せる。

議論マップを全画面にしている本人も「AIに話す」で調査を頼める。結果が届くと通知が出て、「参考資料を開く」で出典を確認し、「どうぞ」で読み上げを許可できる。参加者の映像は小窓で続く。

**カード連携の目標（会員の部屋では後続実装）**　次の操作は現在、マップデモで発言例とサンプル資料を使って試せる。

- 議論マップに未確認の質問があるときは、そのカードの「AIに調べてもらう」を押す。質問と対象の候補・条件を引き継ぐので、入力したり読み上げたりする必要はない。
- 新しく気になったことは「AIに話す」を押して、「ここ、機材込みでいくらか調べて」のように頼める。直前の会話から会場と条件を引き継ぎ、対象が絞れないときだけ聞き返す。同じ質問がすでにマップにあれば、その項目を使う。新しい質問なら該当する候補に確認事項を追加する。

どちらから頼んでも、同じ質問を二重に調べない。依頼した項目には「AIが調査中」と表示する。人が確認中の項目をAIが引き取ることはない。参加者は話し合いを続けられる。

AIメンバーは公開資料を調べ、元の項目と部屋の「参考資料」に質問・短い回答・出典を表示する。数値や事実の横に資料名・発行元と元の表や文書へのリンクを置き、数値には対象期間・範囲・単位を添える。資料で確かめられなければ理由を示し、項目は未確認のままにする。見つかった結果はすぐ全員の画面に出す。音声で報告するのは、AIが挙手し、参加者が「どうぞ」を押した後だけ。調査結果だけで候補を採用・見送りにしない。

## グループに分ける（削る候補）

1. 主催者が部屋の中で「グループに分ける」を押す。分け方（自動か手動か）は未決定。
2. 各グループに別のAIメンバーが入り、それぞれ進め方を決めて進める。
3. 主催者は俯瞰画面で、各グループのパート・残り時間・発言の偏り・合図を見て、必要なグループに入る。
4. 主催者が「全員を戻す」を押すと元の部屋に戻り、AIメンバーが各グループに発表を振る。

俯瞰画面では、主催者の対応が必要なグループを先頭に並べる。順番の案は「主催者を呼んでいる → 沈黙が続いている → 一人に偏っている → 脱線」。

- 進行メモ：右側に開閉できるパネルとして置く。中にはパートが並び、各パートを開くとメモが見られる。パネルを閉じると映像が広がる
- 字幕：映像の下に重ねて出す
- 本人だけへの通知：操作ボタンの上に小さく出し、数秒で消す
- 全体へのお知らせ（再接続中・AI停止など）：画面の上に出す
- 参考資料：その部屋での調査回答と出典を表示する

色・線・文字などの見た目は[デザイン](design.md)に従う。方向性は「ブロック」（太い線、はっきりした色、ずらした黒い影）に決めた。

初期版はPCの画面で作る。スマートフォン対応は後回しにする（11月8日に決定）。

これは必要な情報と操作を整理した案であり、別ページとダイアログの使い分けは実装時に決める。`"use client"`はログイン操作・入室前確認・部屋・俯瞰画面などブラウザ処理を使う入口に付け、ほかはサーバー描画を基本にする。

## 提出範囲

提出とコードフリーズは11月10日19:00（ハッカソンのキックオフ資料による）。

時間が足りなくなったときは、削る候補 → その次の順に外す。必須の範囲は外さない。

うまく動かないときの逃げ道は、別の版を作らず製品の中に持つ。

- Geminiが進め方の案を作れないときは、決まった型を出す。
- 文字起こしがうまくいかないときも、進め方とメモは画面から直せる。
- AIメンバーが止まっても、会話・残り時間・パートの進行は続く。

複数の部屋の型、資料のアップロード、写実的な映像アバター、成績・評価、録画は提出範囲に含めない。

## 動作の合格条件

### 必須

- Googleログインした利用者ごとに、FirestoreにUIDを文書IDとするプロフィールを一件保存する。初回の表示名と登録日時は、ログインし直しても保持する。登録に失敗した場合は画面から再確認できる。
- 別回線の2〜3端末で、参加者の映像・音声とAIメンバーの声を共有できる。
- 開始すると全員の画面に「進め方はどうしますか？」と表示される。話した内容に合わせてAIメンバーが進め方の案を直し、進行メモに出る。
- 3分たっても確定しないときは、その時点の案で始まる。Geminiが案を作れないときは、決まった型で始められる。
- 二人がほぼ同時に進め方を確定・変更しても、反映されるのはどちらか一方で、もう一方には最新の進め方が表示される。
- 一人が変更案を確認する間に別の人がメモを追記しても、承認した予定とメモの両方が残る。将来のパート間で時間を振り替えても、今のパートの残り時間は動かない。
- 各パートを開くと、そのパートのメモが読める。AIメンバーと参加者が同時に書き足しても、どの項目も消えない。メモに発言者の名前は出ない。
- AIメンバーが声を出すのは、「AIに話す」への返答と「どうぞ」を押された後だけ。開始・時間切れ・長い沈黙・振り返りでも、操作がなければ音声は出ない。手を挙げた表示が全員の画面に出る。
- 「AIに話す」を押した人が考えるための間を置いても、話し終える前に返答を始めない。話し終えると、その発言と直前の会話を踏まえて答える。押した人以外の声では、返答が始まらない。
- AIメンバーが話している途中で人が話し始めたら、AIメンバーが話すのをやめる。
- AIメンバーの発話が、字幕でも全員に表示される。
- 振り返りまで進み、本人が「言いたいことを話せたか」に答えられる。
- 部屋が終わると、参加者のホームにノートとして残る。開くと進め方と各パートのメモが読め、振り返りの回答は本人のノートにだけ出る。参加していない利用者は読めない。
- 文字起こしは、部屋が終わった後に残らない。
- 招待コードを入力しても、招待リンクを開いたときと同じく入室前確認へ進む。
- 発言時間と振り返りの回答は本人だけが取得できる。主催者や他の参加者は、APIやデータを直接読んでも個人の値を知ることができない。
- 途中参加・切断復帰のときに、進め方・今のパート・残り時間・メモに合流できる。
- 部屋の参加者以外は、進め方・パート・残り時間を変更できない。主催者以外は部屋を終えられない。画面の操作を迂回しても拒否される。
- AIワーカーを名乗る提案は、自分たちのワーカーのIDトークンが付いている場合だけ受け付ける。
- 延長が確定した後に、延長前の終了予定時刻に基づく提案が届いても、全員の画面は同じパートにとどまり、延長後の残り時間を表示する。
- 同じ切り替えの提案を繰り返し受けても、パートが進むのは1回だけ。
- 主催者や話している人が退室しても、残りの参加者の話し合いが続く。
- 同じ人が退室・再入室しても、その部屋の参加者としては一人と数える。退室後も初回の参加記録は残り、終了後に本人がノートを開ける。
- AIメンバーが止まっても会話・残り時間の表示が続き、終了予定時刻を過ぎればパートも進む。AIが止まっていることが画面に出る。
- 端末の時計がずれていても、全員の残り時間の表示がそろう。許容する差は実装時に決める。
- 同意していない利用者や参加条件を満たさない利用者は入室できず、他の部屋のデータも取得できない。
- 音声、文字起こし、メモ、認証情報をアプリのログやエラー応答へ出さない。

### その次を足すとき

- 名前と質問を一息で言っても質問の全文を受け取れる。「どうぞ」を押すと、AIメンバーがその質問に応える。答えを待つ間、タイルに「考えています」と出る。
- カード連携の後続実装では、未確認カードから1回押すか、「AIに話す」から同じ質問を頼むと、同じ候補に一件の調査が表示される。別端末から同時に頼んでも重複しない。隣の未確認事項や、人が担当している確認事項の状態は変わらない。
- カード連携の後続実装では、調査が終わると、元のカードと参考資料から別端末の参加者も同じ回答と出典を開ける。リンク先で数値・対象年・単位を照合できる。人が話している間も結果は届き、AIの声は割り込まない。
- 根拠となる資料を取得できなかった場合は、その旨が部屋に表示され、参加者は話し合いを続けられる。
- 名前に似た普段の言葉（例：名前が「ミナ」なら「皆さん」）では反応しない。
- 合図を送ると、AIメンバーが送り主を明かさずに伝える。他の参加者や主催者が、APIやデータを直接読んでも送り主を知ることができない。
- 途中参加・切断復帰のときに、その部屋のメモと参考資料を見返せる。
- 会議後は、途中で退室した人もノートから共有済みの調査回答と出典を読み返せる。一度も入室していない利用者が直接取得しようとすると拒否される。
- 同じ会場で決まりそうな場面を、料金が未確認・確認中・確認済みの3通りで試す。AIが料金について問いかけるのは未確認のときだけで、確認中は参加者の報告を待つ。
- 会場案と料金が別々の人の発言でも、マップ上の同じ候補から両方の発言をたどれる。参加者が決定事項を候補に訂正した後は、AIもその会場を候補として扱う。

人数上限や時間などの数値が決まったら、境界値の合格条件を追加する。AIが話し始めるまでの遅れ、日本語の文字起こしと発話の品質は実接続で確かめ、画面のモックだけで合格にしない。

## 11月6日版から方向を変えた理由

旧案は「AI先生が授業をする教室」と「友達との勉強部屋」の二つのモードだった。次の問題があったため、話し合いの場をAIメンバーが回す形に変えた。

- 授業の台本・スライド・音声を作り続ける人がいない。
- 知らない人と同じ時刻に集まる必要があり、利用者が少ないうちは成り立たない。
- AIの講義を聞くだけなら一人で見れば足り、一緒に受ける理由が薄い。資料を音声の解説にする機能は既存のサービスにもある。

新しい案では、主催者が用意するのはお題と合計時間だけで、招待した人と集まる。AIの役割は、一人では起きない「話し合い」を回すことにある。

引き継がないもの：教室一覧、講義の台本と音声の事前生成、講義中の音声送信の制限、サーバーで強制する挙手順の発言権、勉強部屋の教材への質問。

引き継ぐもの：参加者同士の映像・音声の共有、AIの見た目と声のプリセット、18歳以上とGoogleログイン、招待リンクでは管理権限を得られないこと、進行の状態をサーバーだけが確定すること。
