# 未成年向け AI 教室の API 代替候補

確認日：2026-11-06。ユーザーの最新条件は「高校生以下が当初から対象」「Google Meet は必須ではない」。対象に13歳未満を含むかは未確定。OpenAI Docs の公式文書を検索して本文取得済み。

## OpenAI API は未成年向けに使えるか

### Takeaway
OpenAI API は未成年向けアプリを一律に禁止する形ではなく、未成年向けサービスの追加保護を公式に説明している。有力な実装候補だが、年齢・個人データ・利用形態に応じた条件がある。

### Cited Findings
- 公式 Under-18 API guidance は、未成年への年齢相応の説明、コンテンツフィルタ、監視・通報・危険時のエスカレーション、必要に応じた年齢確認を示す。適用される児童保護・プライバシー法への準拠も求める。13歳未満、または適用されるデジタル同意年齢未満の子どもの個人データを扱う前に、API の Zero Data Retention（ZDR）を実装するよう明記している。— [Under-18 API guidance](https://developers.openai.com/api/docs/guides/safety-checks/under-18-api-guidance)

### Inferences
- 13〜17歳を対象とする日本向け学習アプリは、この追加保護を設計に組み込む前提で検討できる。「OpenAI に替えれば無条件に使える」という結論ではない。
- 小学生等を含める場合はZDRの可否が先に決まる設計条件。保護者の同意だけでZDR要件が不要になるとは読めない。
- 設計提案として、運営側がAPIを契約・管理し、自社サーバーから呼び出す構成を想定する。生徒全員へChatGPTアカウントやAPIキーを持たせる構成にはしない。契約者自身に課される年齢条件は本調査では断定しない。

### Gaps
- 正確な保護者同意・契約能力の要件は、対象国、年齢、学校契約か家庭向け提供かによる。Consumer ChatGPT の最低年齢をそのまま独自APIアプリへ適用してはいけない。
- 本ノートはAPI側の開発者ガイダンスを根拠とする。OpenAI Services Agreement の具体的なアカウント年齢条項、当該チームへの個別契約条件は未確認。

## ZDR と教材アップロードは両立できるか

### Takeaway
ZDRは設定値を1つ変えれば使える機能ではなく、OpenAIの事前承認が必要。対象エンドポイントとモデル・機能の条件を含めて確認する必要がある。

### Cited Findings
- 標準の不正利用監視ログは通常最大30日保持される。ZDRは事前承認と追加条件への同意が必要で、承認後に組織・プロジェクトに設定する。`store:false`だけでは不正利用監視ログの非保持を意味しない。— [APIデータ管理](https://developers.openai.com/api/docs/guides/your-data)
- 同ページでは `/v1/responses`（制限あり）、`/v1/realtime`、音声の文字起こし・合成がZDR対象。`/v1/files`、`/v1/vector_stores`、`/v1/conversations`は対象外。画像・ファイルには児童性的虐待コンテンツ検知時の保持例外があり、一部モデル・機能にも制限がある。— [APIデータ管理](https://developers.openai.com/api/docs/guides/your-data)

### Inferences
- 13歳未満を含む場合の案：教材原本は自分たちのストレージで部屋ごとに管理し、個人情報を扱う前に承認済みZDR構成を確保する。AIへ送る本文を必要最小限に絞り、会話履歴も自分たちで短く管理する。ファイルを恒久アップロードする便利機能へ無条件に寄せない。
- 氏名を削除するだけでは、音声・会話・手書き答案から識別できる可能性が残る。ZDRが未承認の状態を「匿名だから大丈夫」と扱わない。
- 自分たちのサーバー、会議配信サービス、ログ・分析サービスの保存は、OpenAIのZDRの外側。音声を録画保存しない設定、保存期間、削除、アクセス制御を別途設計する。

### Gaps
- チームがZDR承認を受けられるか、申請にどれほどかかるかは未確認。一般公開・小学生向け実証を開始できると現時点では保証できない。
- 採用する最新モデルが、実際の組織でZDR対象かはモデル選定・契約段階で確認する。エンドポイントが対応していることだけでは十分ではない。

## 実装の優先案と Anthropic の位置づけ

### Takeaway
まずは「STT（文字起こし）→教材に基づく回答生成→出力確認→TTS（読み上げ）」を基準にする。OpenAI API は候補として明確だが、小学生を含めるならZDR承認を前提条件として扱う。Anthropic API も未成年向け提供を想定している。

### Cited Findings
- Anthropic は、組織がAPIを未成年向け製品へ組み込む場合の追加対策を公式に案内している。2026-03-16のヘルプは年齢確認、コンテンツ制御、監視・通報、法令準拠、AIである旨の開示を挙げる。— [Organizations Serving Minors](https://support.claude.com/en/articles/9307344-responsible-use-of-anthropic-s-models-guidelines-for-organizations-serving-minors)
- 2024年の公式発表にも、試験対策・学習支援などで、追加保護とAI開示を伴う未成年向けAPI組み込みを認める方針が明記される。— [Anthropicの方針発表](https://www.anthropic.com/news/updating-our-usage-policy)

### Inferences
- 推奨する小さな構成：会議音声はLiveKit等、授業進行は自分たちのサーバー、AIはOpenAI API、音声は同APIの文字起こし・合成。最初は一人ずつ質問できるようにし、回答文を確認してから全員へ同じ音声を配信する。音声を直接生成・配信する方式より、誤答や不適切回答を流す前に止める地点を作りやすい。
- OpenAI Realtime は低遅延候補だが、直接音声を再生する構成では配信前の確認との両立が難しくなる。MVPで自然な割り込み会話まで同時に狙う必要はない。
- Anthropicはテキスト推論の代替候補。未成年向けAPIについて説明があることは確認できたが、STT/TTSやデータ処理の契約を別に検討する必要がある。「Anthropicなら小学生でも追加手続き不要」とは言えない。

### Gaps
- Anthropic AUPの通常URLは取得時に2026-11-12発効の将来版を示したため、11月6日時点で発効済みの規約としては引用しない。上記の3月16日ヘルプ・以前の公式発表を条件付き候補の根拠にした。採用時には適用規約を確定する。
- Googleハッカソンの他社AI利用可否、Google Cloud/Gemini利用必須条件は別途大会要件の確認が必要。Google Cloudを認証・保存・アプリ配信に使うことと、GeminiをAI推論に使うことは分けて検討する。
