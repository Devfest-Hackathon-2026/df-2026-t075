# 2人の声で議論マップを試す

主催者のMacで [デモの入口](http://127.0.0.1:3117/demo/map/live) を開き、名前と同意を入力して部屋を作る。「メンバーを招待」からリンクをコピーして相手に渡す。相手は自分のPCのChromeでリンクを開き、別の名前で入る。各自イヤホンを着け「マイクをオン」にする。主催者用の localhost のリンクを相手に渡しても接続できない。

たとえば1人目が「次の勉強会をどこで開く？ 駅前の図書館はどう？」、2人目が「駅から近いから賛成。私が予約するね」と話す。自由に話してよい。字幕とマップは両方の画面に表示される。カードを選ぶと誰が何を言ったかを見返せる。マップを待つ間も会話は続けられる。「前回 ○秒」はサーバーが発言の区切りを受け付けてから、待ち時間・文字起こしを経てマップに反映するまでの時間（発話末尾の無音待ちと表示への通信は含まない）。

試し終わったら主催者が「部屋を終了」→「終了して消去」を押す。同じ招待リンクは再利用できない。

## 主催者のMacで起動する

Node 22、依存パッケージ、Cloud Speech-to-Text・Vertex AIを利用できるGoogle CloudプロジェクトとADCを用意する。Webの `.env.local` の `GOOGLE_CLOUD_PROJECT` と必要に応じて `GOOGLE_APPLICATION_CREDENTIALS` を使う。Googleの利用は課金対象。2台のPCで試すには `cloudflared` をPATHに置く。

```sh
npm run build
npm run demo:live-map -- --share
```

この起動は本番のFirebase Hosting、Cloud Run、Firestore、通常の部屋を変更しない。主催用のポート3117と参加用の3118はどちらも127.0.0.1のみにバインドする。`--share` では部屋を作ったときだけ[Cloudflareの一時トンネル](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)を参加用ポートに開く。HTTPS/WSSで相手のPCから直接参加でき、主催者用ポート・通常のアプリ・運用APIは転送しない。招待なしに発言・音声・マップを送受信することはできない。招待リンクを知る人が参加できるので参加者にだけ渡す。部屋終了・有効期限・全員の切断から1分で一時接続も閉じる。ホストプロセスは次の部屋を待つだけで、Ctrl+Cで止められる。`--share` なしなら同じMacの別のブラウザでのみ試せる。

この検証室は招待リンクと表示名を使う。製品のGoogleログイン済みの部屋、LiveKitの音声テスト、台本の再生とは独立しており、カメラやAIの読み上げは使わない。

## デモの範囲

- 1部屋30分・4人まで。音声・文字ともに発言の総数に上限はない。両端末の自分のマイクだけを16 kHzのPCMにし、相手にはそのまま中継する。約1秒の無音かマイクオフで発言を区切り、24秒を超える発話は分割する。
- 短い音声を[Google Speech-to-Text V2](https://docs.cloud.google.com/speech-to-text/docs/reference/rest/v2/projects.locations.recognizers/recognize)で日本語の字幕にし、評価用台本と同じ分類定義・Vertex判定を使う。識別は端末ごとの参加者名で、同じマイクの前にいる複数人の声を識別する機能ではない。
- 音声認識の完了順が逆でも、部屋が受け付けた発言順にマップを更新する。待ちが12件に達したら新しい発言の判定を受け付けられないことを発言者に表示する。推論に失敗した場合は主催者が再試行・スキップできる。文字起こしに失敗した発言は文字で再入力できる。
- 判定ごとにAIへ渡すのは、その時点のマップ全体と直近60件分の字幕。部屋では最初からの字幕を見返せる。以前のカードも更新でき、カードから元の発言をたどれる。
- 音声・字幕・マップはアプリのDBやログに保存しない。サーバーのメモリだけを使い、終了時に破棄する。同じタブでの再接続は部屋が存続している間だけ有効。ブラウザには再接続用の鍵だけをタブ単位に持つ。
