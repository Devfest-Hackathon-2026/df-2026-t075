# デザイン

2026年11月8日時点。AInote の画面の見た目を実装する人が、この文書だけで同じ見た目を作れるようにまとめる。方向性は「ブロック」（太い線、はっきりした色、ずらした黒い影）に決めた。画面の構成と機能は[アプリ要件](app-requirements.md#画面構成)に従う。

部屋の画面に加え、トップ・ホーム・ノート・部屋の作成・招待リンクのダイアログ・入室前確認・エラーの各画面にも当てはめた（[画面ごとの決まり](#画面ごとの決まり)）。

## 考え方

- 強い色が多いテイストなので、色ごとに意味を一つだけ持たせる。同じ色が別の意味で出てこないようにする。
- 広い面は紙色にし、線・影・強い色は小さな面積に使う。全部を強くすると、長時間の話し合いで目が疲れる。
- 影は「押せる」の合図にする。押せないものには影を付けない。
- 映像が主役。ブロックの装飾が映像より目立たないようにする。

## 色

| 名前                     | 値        | 意味・使う場所                                                       |
| ------------------------ | --------- | -------------------------------------------------------------------- |
| 紙                       | `#FFFDF5` | 背景。広い面はここ。真っ白より目が疲れにくい                         |
| 墨                       | `#111111` | 線、文字、主ボタン、名前ラベル、字幕の背景                           |
| 黄（いま）               | `#FFC93C` | 今のパート、残り時間、AIの挙手、本人だけへの通知                     |
| 青（AI）                 | `#3D7BFF` | AIメンバーのタイル、「考えています」                                 |
| 緑（できた）             | `#2BB673` | 終わったパート、振り返りの「話せた」                                 |
| 赤（止める・聞いている） | `#FF5A4E` | 退室、マイクのオフ、「AIが聞いています」の印、全体のお知らせ（障害） |
| 固定の行                 | `#EFEDE4` | 進め方の案で、削れないパート（振り返り）                             |

人の見分けには淡い色を使う。カメラがオフの人のタイル背景とアイコンに、入室順に割り当てる。淡い色には意味を持たせない。

| 名前    | 値        |
| ------- | --------- |
| 見分け1 | `#FFD1CC` |
| 見分け2 | `#CFF2DF` |
| 見分け3 | `#FFEDB8` |
| 見分け4 | `#E4DAFF` |

黄・青・緑・赤の上に置く文字は、墨（黒）にする。この青と赤に白い文字を載せると、読みやすさの基準（WCAG AA、小さい文字で4.5:1）を満たさないため。

黄色は「いま」の意味で何か所にも出るので、同時に増えすぎないようにする。本人だけへの通知は数秒で消す。振り返りの「少し」など、「いま」と関係ない選択肢には黄色を使わない。

## 線・影・角丸・余白

| 項目   | 値                                                                                                                                                    | 使い方                                                                         |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 線     | 2px、墨                                                                                                                                               | 部品の外枠（ボタン、チップ、タイル、パネル、入力欄）                           |
| 強い線 | 3〜4px、墨                                                                                                                                            | 「いま」のもの。今のパートは3px、話している人とAIが話しているときのタイルは4px |
| 影     | ぼかしなし。高さ40px以下の部品は右下に3px、それより大きい部品は4pxずらす。白や色のボタンの影は墨で塗る。墨のボタンの影は、紙色の塗りに墨の線2pxで描く | 押せるものにだけ付ける。押すと部品が影の位置まで沈み、影が見えなくなる         |
| 角丸   | 8px                                                                                                                                                   | タイル、カード、ボタン、チップ。パートの番号の小さな四角は4px                  |
| 余白   | 8pxの倍数。詰めるところだけ4px                                                                                                                        | 部品の間、パネルの内側                                                         |

墨のボタンに墨の影を付けると、ボタンと影の境目がなくなり、ボタンが太ってずれたように見える。そのため、墨のボタンだけは影を「線だけの影」にする（11月8日に修正）。

カメラ映像そのものには線や装飾を重ねない。線はタイルの外枠だけに付ける。

## 文字

| 用途                             | フォント         | 大きさ                                                     |
| -------------------------------- | ---------------- | ---------------------------------------------------------- |
| 見出し、残り時間、タイルの頭文字 | Dela Gothic One  | 見出し14〜20px、残り時間22px（大きく見せる場所は42pxまで） |
| 本文、ボタン、メモ、字幕、通知   | IBM Plex Sans JP | 本文14px、補足12px、字幕14〜16px                           |

本文の太さは標準（400）と少し太い（500）の2段階だけにする。行間は本文1.7、字幕1.5。

本文フォントは、11月7日に IBM Plex Sans JP に決めた。M PLUS 2、Murecho、BIZ UDPGothic、Zen Maru Gothic、Zen Kaku Gothic New と比べ、少し機械的で骨太な形がブロックの硬さと合い、数字と英字にも個性があることを理由にした。どれも Google Fonts で公開されている（SIL Open Font License）。

### 読み込み方

Next.js の `next/font/google` は、ビルドの途中でGoogle Fontsからフォントをダウンロードする。このリポジトリは「ビルド時に外部へ接続しない」方針なので、使わない。

提出版では、ブラウザが Google Fonts のCSSを読み込む形にする（`display=swap`）。日本語フォントは大きいが、Google Fonts は使う文字の範囲ごとに分けて配信するので、必要な分だけ読まれる。読み込みが遅いときや失敗したときは、端末の標準フォントで表示されるだけで、画面は使える。E2Eテストはフォントの読み込みに依存させない。

外部への接続を避けたくなったら、フォントのファイルをリポジトリに同梱する。日本語フォントは数MBあるので、そのときは使う文字の範囲を絞る。

## アイコン

Material Symbols の角型（Sharp）を、太めの線で使う。ブロックの角ばった形に合うため。アイコンフォントは大きいので、npm で配布されている SVG のパッケージから、使うアイコンだけを読み込む（パッケージ名は導入時に確認する）。

アイコンだけのボタンには、ツールチップと読み上げ用のラベル（`aria-label`）を必ず付ける。合図（旗）のように意味が分かりにくいアイコンは、初回だけ説明を出す。

## AIメンバー

- 青いタイルの中央に、白い四角い顔（角丸6px、線2px）。目は墨の小さな正方形、口は墨の横棒。
- 聞いている：顔がゆっくりうなずく（上下に3px）。
- 挙手：タイルの右上に黄色のブロック（手のアイコン）が出て、小さく跳ねる。挙手の間は、タイルの下に「どうぞ」ボタン（白・影あり）を出す。
- 「AIに話す」：タイルの下に常に置くボタン（白・影あり）。押している間は赤（聞いている）にし、ボタンの文字を「話し終えた」に変える。話しかけている人の名前をタイルの上に出す。
- 考えている：目を細め、口の位置に3つの点が順に光る。
- 話している：口の横棒が音声に合わせて伸び縮みする。タイルの線が4pxになる。
- プリセットの違い：タイルの青は共通にし、顔（目の形）だけを変える。四角い目、細い目、丸い目など。どのプリセットでも、青いタイルを見ればAIだと分かるようにするため。

動きは `transform` と `opacity` だけで作り、`prefers-reduced-motion` が有効な端末では止める。

## 部屋の画面

- 上部：墨の帯にお題、その右に「AIが聞いています」のチップと残り時間のブロック。
- 中央：映像タイルを2列で並べ、AIメンバーは最後の枠に固定する。
- 右：進行メモのパネル（幅は約220px、閉じられる）。閉じると映像が横に広がる。
- 下：字幕、その下に本人だけへの通知、いちばん下にアイコンボタンと退室ボタン。

## 画面ごとの決まり

### 共通

- 上部のバーに、Dela Gothic One で「AInote」と書く。ロゴの画像は作らない。右端にログイン中の人のアイコン（見分けの淡い色に頭文字）。
- 主ボタンは一つの画面に一つだけ。
- ダイアログは押せないので影を付けない。代わりに外枠の線を3pxにし、後ろを墨の半透明（55%）で暗くする。
- エラーや案内の文は、何が起きたかと、次に何をすればいいかを一文ずつ書く。

### トップ（`/`）

- 左に大きな見出し（Dela Gothic One、30px前後）「AIも、話し合いのメンバー。」と、2文程度の説明。
- その下に「Googleでログイン」のボタンと「18歳以上の方が対象です」。
- 右に、実際の部品（映像タイル3枚とAIメンバーのタイル、挙手のブロック）を少し傾けて重ねた絵。絵のために別の画像は作らない。
- 下に特徴のカードを3枚（割り込まずに手を挙げる、進め方を一緒に決める、パートごとにメモが残る）。カードは白で、アイコンの四角だけが意味の色（挙手＝黄、AI＝青、メモ＝緑）。

Googleでログインのボタンは、ブロックの影や太い線で装飾しない。Googleのブランドのガイドラインに沿い、公式のロゴを変えずに使い、色と形はガイドラインで選べる範囲から選ぶ。実装時は、Googleが配布しているボタンの素材を使う。

### ホーム（`/home`）

ホームでできることは「部屋を作る」と「招待で入る」の二つなので、部屋の状態の一覧は置かない。上から次の順に並べる。

1. 参加中の部屋の帯：退室した部屋が続いているときだけ、黄（いま）の帯で「参加中の部屋があります」と「戻る」を出す。
2. 入口：左に「部屋を作る」（主ボタン、大きいブロック。補足に「お題と時間を決めて、招待リンクを作る」）、右に「招待コードで入る」（白いカードに入力欄と「入る」）。リンクを受け取った人はリンクを開けば直接入れるので、コードの入力は予備。
3. ノート：終わった話し合いを新しい順にカードで並べる。カードの上端に見分けの淡い色の帯、お題、日付・パート数・主催か参加か（文字だけ。色のチップは付けない）、メモの最初の数項目、参加者のアイコン。カードは押せるので影あり。

初めて使うときは、ノートの場所に点線の枠で「最初の話し合いを始めましょう」と、話し合いが終わるとノートが残ることを書く。

### ノート

- 部屋の進行メモを読み取り専用にして使い回す。すべてのパートを開いた状態で、終わった印（緑）を付ける。
- 上にお題、日付・合計時間・パート数、参加者のアイコン、「メモをコピー」（副ボタン）。
- 振り返りの回答と発言時間は、本人のノートにだけ点線の枠で出す。

### 部屋の作成（`/rooms/new`）

- 入力はお題・合計時間・AIメンバーの3つだけ。
- お題の入力欄は、入力中だけ線を3pxにする。
- 合計時間は15・30・45・60分の横並びの選択。選んだものは墨の背景に紙色の文字（意味の色ではなく、選んでいることの表示）。
- AIメンバーは3つのプリセットをカードで並べる。選んだカードは線4pxと墨のチェック。各カードに「声を聞く」。
- 点線の枠で「進め方は決めなくて大丈夫です。部屋の中で、AIメンバーと話し合って決めます」と添える。

### 招待リンクのダイアログ

- 部屋を作った直後と、部屋の中のメニューから開く。
- 見出し「部屋ができました」、説明、招待リンクとコピーボタン。コピーしたら緑のチップで「コピーしました」。
- ボタンは「あとで」（副）と「部屋に入る」（主）。

### 入室前確認（`/rooms/[id]/join`）

- 左：カメラの映像、マイクとカメラのアイコンボタン、マイクの音量（声が入ると黄のブロックが伸びる）、マイクとカメラの選択、「カメラなしで参加する」。
- 右：部屋のカード（お題、主催者、時間、待っている人とAIメンバーのアイコン）、AIメンバーの説明（青のカード）、同意のチェック、「入室する」（主ボタン）。
- 「入室する」の下に、このボタンでAIの声の再生も許可されることを小さく書く。
- 同意せずに「入室する」を押したら、ボタンを無効にするのではなく、同意が必要なことをその場で伝える。

### エラー

- 中央に、少し傾けた赤い四角のアイコン、見出し、理由と次にすることの文、「ホームへ」（主ボタン）。
- 同じ形で出すもの：招待が使えない（期限切れ・部屋が終わった）、参加条件を満たさない（18歳以上）、マイクとカメラが使えない（ブラウザの設定の直し方を案内）。
