# 13〜17歳向けAI教室の技術選定

2026年11月6日確認。対象を最初から13〜17歳とし、Meetそのものは使わない条件で考えると、**Googleの基盤で教室を作り、AI推論には未成年向け提供を想定したAPIを組み込む構成が有力です。** 現時点では、実装負担を抑えるOpenAI APIを第一候補、Googleのモデルを自分たちで動かすGemma 4を比較候補とします。Gemini API・Cloudの生成AIサービスにある年齢条項は、保護者同意やLiveからテキストへの変更だけでは解消しません。([Gemini API規約](https://ai.google.dev/gemini-api/terms)、[Cloud規約20(d)](https://cloud.google.com/terms/service-terms))

大会資料35〜36ページは、指定のGoogle実行基盤を一つ以上使い、Google技術を主に使うことを求めています。**他社LLM APIの内部利用自体は禁止されていません**が、Google技術としての加点にはならず、他社AIツールが主役のプロダクトは対象外です。Gemini必須とは記載されていません。認証、共同学習の状態同期、教材管理、授業制御をGoogle側の主要機能として実装する方針ですが、AI先生が「他社AIツールがメイン」に該当するかは文面だけで確定できません。単に外部AIと通話をFirebaseの画面で包む構成では弱いため、運営への確認が必要です。（出典: ユーザー提供の「[DF Hack26] Kickoff Slide.pdf」35〜36ページ。配布PDFはリポジトリから削除済み）

| 候補 | このプロダクトとの適合 | 主な負担・未確認点 |
|---|---|---|
| OpenAI API | 未成年向けアプリの公式ガイダンスがあり、音声認識・回答生成・読み上げを組み合わせられる | 年齢相応の保護を実装する。Google技術としての加点対象にはならない |
| Gemma 4の自己運用 | Google公式の想定用途にK-12数学指導があり、モデルはApache 2.0 | GPU運用、日本語の教育品質、安全対策を自分たちで担う。利用するクラウド・音声サービスの条件は別途確認 |

OpenAIのガイダンスは、年齢相応の説明、コンテンツ制御、監視・通報と対応経路などを求めています。Gemmaの学校向け想定用途も、完成したサービス全体の許諾や安全性を保証するものではありません。またGemmaをGemini API経由で呼ぶ方法では、そのAPIの条件が残ります。([OpenAI未成年向けガイダンス](https://developers.openai.com/api/docs/guides/safety-checks/under-18-api-guidance)、[Gemma想定用途](https://ai.google.dev/gemma/intended_use_statement)、[Gemma 4ライセンス](https://ai.google.dev/gemma/apache_2))

**推奨構成は、Reactの画面、Firebase Authentication、Firestore、Cloud Storage、Cloud Runの制御API、LiveKitの通話、サーバーから呼び出すOpenAI APIです。** Firestoreで授業段階・質問待ち・発言者を共有し、Cloud Run側で入室と操作権限を確認します。AIは部屋ごとに一つの回答を生成し、全員へ同じ内容を配信します。生徒にAPIキーやChatGPTアカウントを持たせる構成にはしません。

音声はまず「質問ボタン→文字起こし→教材に基づく回答生成→出力確認→読み上げ」とします。直接音声を返す方式より待ち時間は増えますが、不適切な回答を全員へ流す前に止める処理を挟みやすくなります。OpenAI Realtimeが未成年向けに一律禁止という意味ではなく、最初の実装で管理しやすい方式を選ぶ判断です。AIが読む授業部分は確認済みの台本を使い、動的な生成は質問へのヒント・回答から始めます。

解説中のミュートは画面操作だけでなく、サーバーで音声配信を制御します。質問は挙手順に一人ずつ許可し、その人をAIの聞き取り対象にします。友達部屋も同じ通話・教材・AIの機能を使い、自由会話と「AIに質問」のルールを切り替えます。通話のLiveKit Cloudでは契約者の18歳以上条件と、生徒というエンドユーザーの条件を区別できますが、子ども向け運用の個別承認を得たわけではありません。対象年齢と音声保存の有無を示した確認は残ります。([LiveKit規約](https://livekit.com/legal/terms-of-service)、[データ処理契約](https://livekit.com/legal/data-processing-addendum))

教材原本は部屋ごとのストレージで管理し、AIへ渡す内容を必要な問題・ページに絞ります。録音・答案・会話履歴の保存目的と削除時期を決め、参加者へ説明します。将来13歳未満へ広げる場合は、個人データを扱う前のZDR承認など、今回とは別の条件確認が必要です。([APIデータ管理](https://developers.openai.com/api/docs/guides/your-data))

**最初の提出範囲は、一つの単元、一つの短い教材、2〜4人の共有部屋、一人ずつのAIへの質問に絞るのが妥当です。** 先に友達部屋で共有教材と質問を動かし、同じ基盤へ授業進行を追加します。AIの回答品質は対象単元の問題で確認し、複数端末で進行が一致すること、ミュート中に音声を再送できないこと、他の部屋の教材を読めないことを検証します。GemmaのGPU配備も公式手順はありますが、短い開発期間にモデル運用まで追加する負担は大きく、最初から必須にはしません。([GemmaのCloud Run配備](https://docs.cloud.google.com/run/docs/run-gemma-on-cloud-run))

運営への確認文案は「13〜17歳向けのためGeminiの利用条件を踏まえ、Firebase・Cloud Runで共同授業を制御し、回答生成だけに他社LLM APIを使う構成は審査対象になりますか」です。これは確認用の下書きで、送信していません。契約条件、接続、遅延、授業品質、予算内での稼働は未検証です。
